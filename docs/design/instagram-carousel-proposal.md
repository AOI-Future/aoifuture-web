# AOIFUTURE News Instagramカルーセル設計提案

Status: Proposal
Date: 2026-09-28
Target: Instagram feed, 1080×1350px (4:5)

## Executive decision

現行の「Edition全体を1枚に詰めるカード」をInstagramの主役にせず、**リードニュースを8枚で理解させる「AOIFUTURE EXPLAINED」カルーセル**を標準形にする。

X・LinkedIn・OGP向けの1枚カードは残す。Instagramだけは滞在時間・保存・シェアを目的に別テンプレートへ分岐する。

## なぜ変えるか

現行のInstagramカードは4:5だが、リード解説と複数ニュースの見出しを1枚に載せているため、スマホ表示では本文が小さくなる。ブランド、日付、テーマの階層は明確だが、読者が一度に追うメッセージが多い。QRとURLはあるものの、保存・共有への直接CTAもない。

したがって、情報量を削るのではなく、**同じ一次情報を「一枚一役」に分ける**。

## 推奨テンプレート：AOIFUTURE EXPLAINED（最大8枚・選択式）

8枚は固定必須ではなく**引き出し（引き出しには8種類）**。ニュースごとに成り立つページだけを選び、6〜8枚で構成する。空っぽいページを埋めないための選択規則は「ページ選択規則」を参照。`STOP / FACT / ...` は制作内部の区分名であり、読者には出さない。読者向け見出しは毎回ニュースの内容に合わせた日本語で作る。

### 表紙（旧STOP）

- 役割：スクロールを止める
- 内容：このEditionの一次情報で裏づけられた反直感的な事実または問いを一つ
- 表示：大見出し1つ、補助文1行、`1 / N`、発表主体
- 禁止：根拠のない「9割」「革命」「完全に変わる」
- 表紙見出しは必ず該当itemsの `title` / `source_fact` から導出し、原典と対応しない例を文案として置かない

例（2026-09-27版・Hugging Face relore公開の記事に基づく実例）：

> エージェントは「やり方」を記憶しはじめた — relore公開（HF, 2026.09.26）

### 何が起きたか（旧FACT）

- 発表主体、公開日、成果物を一文で示す
- プロダクト／論文／標準の種別をバッジ表示
- 中央は1つのピクトグラムまたは構成図

### どう動くか（旧MECHANISM）

- 入力 → 記憶 → 次回実行、のような3段階フロー
- 各箱は短句のみ。説明文は1行注釈
- 処理フローを一次情報で特定できないニュースではこのページを作らない

### 何が変わるか（旧CONTRAST）

- Before / After、従来 / 新方式、単発 / 蓄積の2列比較
- アクセント色は結論側だけに使う
- 独立に検証した差分が存在しないニュースでは「発表側の主張 / 独立に確認できた範囲」の2列に切り替え、両者を同じ強さで断定しない

### なぜ重要か（旧SO WHAT）

- AOIFUTURE独自の編集価値を置くページ
- 開発者・運用者の判断がどう変わるかを一つに絞る
- 本文を「事実」「AOIの見方」のラベルで物理的に分離する

### まだ言えないこと（旧BOUNDARY）

- 誇張を防ぐページ
- 未検証範囲、対象条件、単一事例、査読状況などを最大3点
- 警告色で煽らず、薄いパーチメント背景で静かに見せる
- 版が未査読・プレビューなら必ずここに明記する

### 関連観測点（旧RADAR）

- 同じEditionのMAJOR／BRIEFから、リードの意味を補強する2件まで
- 単なる「その他ニュース一覧」にはしない
- 接続を一本の線で示し、「なぜ同じ流れなのか」を一文で結ぶ
- リードと意味の接続を1文で説明できない件は載せない

### 保存用チートシート（旧SAVE）

- 「今日の3点」＋「次に確認する1点」
- CTA：`あとで見返すなら保存` / `同僚に共有`
- スワイプ矢印は置かない

## ページ選択規則

- 必須：表紙／何が起きたか／なぜ重要か／保存用チートシート（4枚）
- 材料が一次情報にある場合のみ追加：どう動くか／何が変わるか／まだ言えないこと／関連観測点
- 判定基準：そのページの本文を、Edition JSONの既存フィールド（`title` / `source_fact` / `selection_reason` / `aoi_note` / `verification` / `source_url`）の実際の記述だけで埋められるか。埋められないページは作成をスキップし、枚数 `N` を6〜8から実数へ落とす
- フィールド欠損時は推測で生成しない。欠損字段を使うページごとスキップし、その場合の最小構成は表紙＋何が起きたか＋保存用（3枚）

## データ導出と出典表示

- カルーセルの全主張はEdition JSONの既存フィールドからのみ導出する（版JSONは書かない — hash契約維持）
- 各スライドのフッターはそのページの主張を支える一次情報を1行で載せる：`出典: <媒体名> <YYYY.MM.DD> <URLまたはDOI/edition ID短縮形>`
- URLが長い場合は `aoifuture.com/news/<edition_id>/#item-n` のアイテムアンカーへ集約し、フルURLは保存用スライドと `share-copy-index.json` に保持する
- 表紙・チートシートにはQRまたはedition IDを必ず置き、保存した1枚だけで原典へ辿れるようにする


## 画面設計

- サイズ：1080×1350px（4:5）
- 安全マージン：左右60px・上下48px。**視覚的ブリッジはこのマージン内に収める**（右端要素はx=1020〜1080の帯のみ。本文・図はx=1020を超えない）
- 最小本文：28px（1080px基準）。Instagramはフィードで約64%（幅約658px相当）に縮小表示され、さらにiPhone幅390pt（@3x=1170px≒等倍換算で0.36倍）では本文が約10pt相当になるため、**28px以下は不可・本文は32px推奨**。合格判定は実機（または等倍キャプチャ）で「本文が読めるか」を目視確認し、数値計算だけに依存しない
- 見出し：56〜80px / 表紙主語：88〜120px
- 1枚の文字量：タイトル込み80字を目安
- 配色（**面積比**の目安）：背景 #071010 約70%、文字・図表枠 #d7cdb0 / #ededed 約25%、アクセント #73ffff 約5%。アクセントは結論・急上昇データ・ブリッジ線にのみ使用
- 進捗：右上 `n / N` / フッター出典（前述の1行出典フォーマット）
- ブリッジ：2〜7枚目の右端に、次ページへ続くシアン線または半分だけ見えるノード


## 視覚言語

装飾イラストではなく、内容に応じて次から一つだけ選ぶ。

- プロセス：3段階フロー
- 差分：Before / After
- 関係：2軸またはノード接続
- 数値：正確な比例棒／ドット
- 時系列：3点タイムライン
- 境界：確認済み／未確認の二領域

「何となくテクノロジーっぽい回路」「出典別件数」「トピック出現率」は、読者の理解を進めないため使わない。

## ニュース種別による差し替え

### 論文

- 表紙：最も強い検証済みの結果
- 2枚目：対象・サンプル・研究デザイン
- 3〜4枚目：方法と結果の再視覚化
- 6枚目：査読状況、外的妥当性、因果の限界
- フッター：ジャーナル／arXiv、年、DOIまたは識別子

### 製品・リリース

- 2枚目：誰が何を公開したか
- 3枚目：処理フロー
- 4枚目：従来との差
- 6枚目：提供範囲、価格・地域・利用条件の未確認点

### セキュリティ・標準

- 3枚目：攻撃／制御経路
- 4枚目：対策前／対策後
- 6枚目：防げない経路と残余リスク

## 既存パイプラインとの接続

- 現行のX 1200×630、LinkedIn 1200×627、Instagram単画像1080×1350の生成は維持する
- Instagram向けに `slide-01.png`〜`slide-0N.png`（N=選択規則で確定した枚数）を追加生成する
- Edition JSONは変更せず、表示層で以下を導出する
  - lead title / source_fact / selection_reason / aoi_note / verification / source metadata / 関連items最大2件
  - 各フィールドが欠損している場合は、そのフィールドを使うスライドをスキップする（前出ページ選択規則）
- `share-copy-index.json` にカルーセル画像配列、出典、CTA文案を追加する
- 8枚を機械的に埋められない場合は、空疎なページを作らず6〜8枚へ縮退する

## 品質ゲート

1. 一枚一メッセージか
2. 390〜430pt相当の縮小表示でピンチなしに読めるか
3. 各スライドの主張がEditionの一次情報で裏づけられるか
4. 事実、AOIの解釈、未確認事項が混ざっていないか
5. 生グラフの簡略化で結論が変わっていないか
6. 右端・フッター・長文に切れや重なりがないか
7. 1〜7枚目の視覚的ブリッジが連続し、8枚目で閉じているか
8. 保存した1枚だけでも出典と文脈が分かるか

## 段階導入

1. 最新Editionのリード1件で8枚の静的プロトタイプを作る
2. 実画像をモバイル縮小してvision review
3. 既存Instagram単画像と並べ、可読性・理解速度・保存CTAを比較
4. 合格後にジェネレーターへテンプレート化
5. Bufferは当初draft-only。実投稿の保存率・完走率を見て自動キュー化を別承認する

## 非目標

- 9本すべてをカルーセルへ詰めること
- 論文図版のスクリーンショット転載
- 根拠のない大数字で表紙を強くすること
- リール化
- 内部スコア、source比率、topic比率の読者向け表示
