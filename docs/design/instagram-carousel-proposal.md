# AOIFUTURE News Instagramカルーセル設計提案

Status: Proposal
Date: 2026-09-28
Target: Instagram feed, 1080×1350px (4:5)

## Executive decision

現行の「Edition全体を1枚に詰めるカード」をInstagramの主役にせず、**リードニュースを8枚で理解させる「AOIFUTURE EXPLAINED」カルーセル**を標準形にする。

X・LinkedIn・OGP向けの1枚カードは残す。Instagramだけは滞在時間・保存・シェアを目的に別テンプレートへ分岐する。

## なぜ変えるか

現行のInstagramカードは4:5だが、リード解説と複数ニュースの見出しを1枚に載せているため、スマホ表示では本文が小さくなる。ブランド、日付、テーマの階層は明確だが、読者が一度に追うメッセージが多い。QRとURLはあるものの、保存・共有への直接CTAもない。

したがって、情報量を削るのではなく、**同じ一次情報を「一枚一役」に分ける**。

## 推奨テンプレート：AOIFUTURE EXPLAINED（最大8枚・選択式）

8枚は固定必須ではなく**引き出し（引き出しには8種類）**。ニュースごとに成り立つページだけを選び、6〜8枚で構成する。空っぽいページを埋めないための選択規則は「ページ選択規則」を参照。`STOP / FACT / ...` は制作内部の区分名であり、読者には出さない。読者向け見出しは毎回ニュースの内容に合わせた日本語で作る。

### 表紙（旧STOP）

- 役割：スクロールを止める
- 内容：このEditionの一次情報で裏づけられた反直感的な事実または問いを一つ
- 表示：大見出し1つ、補助文1行、`1 / N`、発表主体
- 禁止：根拠のない「9割」「革命」「完全に変わる」
- 表紙見出しは必ず該当itemsの `title` / `source_fact` から導出し、原典と対応しない例を文案として置かない

例（2026-09-27版・Hugging Face relore公開の記事に基づく実例）：

> エージェントは「やり方」を記憶しはじめた — relore公開（HF, 2026.09.26）

### 何が起きたか（旧FACT）

- 発表主体、公開日、成果物を一文で示す
- プロダクト／論文／標準の種別をバッジ表示
- 中央は1つのピクトグラムまたは構成図

### どう動くか（旧MECHANISM）

- 入力 → 記憶 → 次回実行、のような3段階フロー
- 各箱は短句のみ。説明文は1行注釈
- 処理フローを一次情報で特定できないニュースではこのページを作らない

### 何が変わるか（旧CONTRAST）

- Before / After、従来 / 新方式、単発 / 蓄積の2列比較
- アクセント色は結論側だけに使う
- 独立に検証した差分が存在しないニュースでは「発表側の主張 / 独立に確認できた範囲」の2列に切り替え、両者を同じ強さで断定しない

### なぜ重要か（旧SO WHAT）

- AOIFUTURE独自の編集価値を置くページ
- 開発者・運用者の判断がどう変わるかを一つに絞る
- 本文を「事実」「AOIの見方」のラベルで物理的に分離する

### まだ言えないこと（旧BOUNDARY）

- 誇張を防ぐページ
- 未検証範囲、対象条件、単一事例、査読状況などを最大3点
- 警告色で煽らず、薄いパーチメント背景で静かに見せる
- 版が未査読・プレビューなら必ずここに明記する

### 関連観測点（旧RADAR）

- 同じEditionのMAJOR／BRIEFから、リードの意味を補強する2件まで
- 単なる「その他ニュース一覧」にはしない
- 接続を一本の線で示し、「なぜ同じ流れなのか」を一文で結ぶ
- リードと意味の接続を1文で説明できない件は載せない

### 保存用チートシート（旧SAVE）

- 「今日の3点」＋「次に確認する1点」
- **NoteへのQRをスライド右下に大きく配置（約200×200px）**
  - 第一候補：該当版のnote記事URL（DailyNewsTrackAのnote_url。Obsidian最終草稿の `note_url:` / `公開URL:` から解決）
  - 記事が未公開・不明のとき： `https://note.com/shugo`（プロフィール）へフォールバック。QR先を空にしない
- QRの隣にCTA文案：`全文はNoteで読めます ／ あとで見返すなら保存 ／ 同僚に共有`
- QR下部に読み上げ可能な縮約URLも1行添える（`note.com/shugo` 等）— QRが読めない環境への保険
- スワイプ矢印は置かない


## ページ選択規則

- 必須：表紙／何が起きたか／なぜ重要か／保存用チートシート（4枚）
- 材料が一次情報にある場合のみ追加：どう動くか／何が変わるか／まだ言えないこと／関連観測点
- 判定基準：そのページの本文を、Edition JSONの既存フィールド（`title` / `source_fact` / `selection_reason` / `aoi_note` / `verification` / `source_url`）の実際の記述だけで埋められるか。埋められないページは作成をスキップし、枚数 `N` を6〜8から実数へ落とす
- フィールド欠損時は推測で生成しない。欠損字段を使うページごとスキップし、その場合の最小構成は表紙＋何が起きたか＋保存用（3枚）

## データ導出と出典表示

- カルーセルの全主張はEdition JSONの既存フィールドからのみ導出する（版JSONは書かない — hash契約維持）
- 各スライドのフッターはそのページの主張を支える一次情報を1行で載せる：`出典: <媒体名> <YYYY.MM.DD> <URLまたはDOI/edition ID短縮形>`
- URLが長い場合は `aoifuture.com/news/<edition_id>/#item-n` のアイテムアンカーへ集約し、フルURLは保存用スライドと `share-copy-index.json` に保持する
- 表紙・チートシートにはQRまたはedition IDを必ず置き、保存した1枚だけで原典へ辿れるようにする。**保存用チートシートのQRはNote（記事URL→未取得ならプロフィール）を標準CTA先とし、qrcodeライブラリで生成。QRは背景 #f2e9d8 / 前景 #10261f のブランド配色でコントラスト比4.5:1以上を維持する**


## 画面設計

- サイズ：1080×1350px（4:5）
- 安全マージン：左右60px・上下48px。**視覚的ブリッジはこのマージン内に収める**（右端要素はx=1020〜1080の帯のみ。本文・図はx=1020を超えない）
- 最小本文：28px（1080px基準）。Instagramはフィードで約64%（幅約658px相当）に縮小表示され、さらにiPhone幅390pt（@3x=1170px≒等倍換算で0.36倍）では本文が約10pt相当になるため、**28px以下は不可・本文は32px推奨**。合格判定は実機（または等倍キャプチャ）で「本文が読めるか」を目視確認し、数値計算だけに依存しない
- 見出し：56〜80px / 表紙主語：88〜120px
- 1枚の文字量：タイトル込み80字を目安
- 配色（**面積比**の目安）：背景 #071010 約70%、文字・図表枠 #d7cdb0 / #ededed 約25%、アクセント #73ffff 約5%。アクセントは結論・急上昇データ・ブリッジ線にのみ使用
- 進捗：右上 `n / N` / フッター出典（前述の1行出典フォーマット）
- ブリッジ：2〜7枚目の右端に、次ページへ続くシアン線または半分だけ見えるノード


## 視覚言語

装飾イラストではなく、内容に応じて次から一つだけ選ぶ。

- プロセス：3段階フロー
- 差分：Before / After
- 関係：2軸またはノード接続
- 数値：正確な比例棒／ドット
- 時系列：3点タイムライン
- 境界：確認済み／未確認の二領域

「何となくテクノロジーっぽい回路」「出典別件数」「トピック出現率」は、読者の理解を進めないため使わない。

## ニュース種別による差し替え

### 論文

- 表紙：最も強い検証済みの結果
- 2枚目：対象・サンプル・研究デザイン
- 3〜4枚目：方法と結果の再視覚化
- 6枚目：査読状況、外的妥当性、因果の限界
- フッター：ジャーナル／arXiv、年、DOIまたは識別子

### 製品・リリース

- 2枚目：誰が何を公開したか
- 3枚目：処理フロー
- 4枚目：従来との差
- 6枚目：提供範囲、価格・地域・利用条件の未確認点

### セキュリティ・標準

- 3枚目：攻撃／制御経路
- 4枚目：対策前／対策後
- 6枚目：防げない経路と残余リスク

## 既存パイプラインとの接続

- 現行のX 1200×630、LinkedIn 1200×627、Instagram単画像1080×1350の生成は維持する
- Instagram向けに `slide-01.png`〜`slide-0N.png`（N=選択規則で確定した枚数）を追加生成する
- Edition JSONは変更せず、表示層で以下を導出する
  - lead title / source_fact / selection_reason / aoi_note / verification / source metadata / 関連items最大2件
  - 各フィールドが欠損している場合は、そのフィールドを使うスライドをスキップする（前出ページ選択規則）
- `share-copy-index.json` にカルーセル画像配列、出典、CTA文案を追加する
- 8枚を機械的に埋められない場合は、空疎なページを作らず6〜8枚へ縮退する

## got-image-2 イラスト表現の適用方針

参考記事（<https://note.com/hidepicchu/n/n1a470da744e9>）の完成例として、次の表現が**制作・後編集を経て仕上げられていることが確認できた**。これらは当該記事における制作事例であり、AOIFUTUREでの再現性そのものは次段階のプロトタイプで実証する課題として扱う。

- 同じ2人物を正面・側面・背面で揃えたキャラクターシート
- 同じ服装・持ち物・年代感を保った複数場面の連続イラスト
- 駅、電車内、移動車両、飲食店など、場所が変わる4ページ程度の短編コミック
- 表情、視線、手振りを使った会話劇と、引き／寄りを混ぜたコマ割り
- 白地・低彩度・線画中心の、AOIFUTUREの現行カルーセルと衝突しにくい画風

ただし、記事の制作例は生成画像だけで完結していない。吹き出し、縦書き、日本語フォント、文字サイズ、尻尾位置は専用の BubbleEditor で後編集され、版管理UIで比較・修正されている。したがって、**got-image-2には人物・場面・構図を担当させ、正確な日本語・数値・出典・CTA・QRは既存のsatori描画に固定する**。画像に文字を書かせた結果を最終稿として採用しない。

### Instagramで狙える上限

1. **編集挿絵（低リスク）**
   - 表紙や「なぜ重要か」の主役ビジュアルを、ニュース内容に即した1場面で描く
   - 人物を使わない抽象図より、読者が状況を一目で理解しやすい
2. **シーン連続（推奨）**
   - 同じ主人公を2〜3枚に再登場させ、「困りごと → 新しい仕組み → 判断の変化」を見せる
   - キャラクターシートを先に固定し、そのシートを参照して各場面を生成する
3. **2人物のミニ会話劇（条件付き）**
   - 3〜4枚で、開発者と運用担当、利用者とAIなどの立場の違いを可視化する
   - セリフは画像生成せず、satori側の吹き出しとして後置きする
4. **短編コミック（技術的には可能、ニュース標準形にはしない）**
   - 参考記事と同程度の複数場所・複数ページの物語表現まで可能
   - ただしニュースの事実密度、制作時間、文字可読性を考えると、毎日の自動生成ではなく特集・週次解説向け

### AOIFUTURE向け推奨構成（ハイブリッド）

**実装面の前提（現行ジェネレーターとの関係）**：現行の `scripts/generate-news-carousel.mjs` は8枚固定・Relore専用ハードコードのプロトタイプであり、本節の「6〜8枚の選択式」はまだ実装していない。got-image-2插图はまず**ジェネレーターとは独立した静的モック（Handoff用の別ディレクトリ）**として制作し、評価合格後にのみジェネレーター側へテンプレートスロット（`illustration_slot`）として実装する。_generator変更はこの設計書が承認されるまで行わない。_

- 1枚目：got-image-2による状況フック＋satoriの見出し
- 2枚目：公式スクリーンショット／製品画像＋検証済み事実（イラストに置換しない）
- 3枚目：satoriで処理フローまたは一次情報の図を再構成
- 4枚目：同じ主人公のBefore／After 2場面で「何が変わるか」を埋める
- 5枚目：主人公と運用者の1往復会話＋AOIの見方
- 6枚目：公式画面＋「まだ言えないこと」
- 7枚目：関連観測点。必要なら小さな共通キャラを案内役にする
- 8枚目：satoriのみの保存用チートシート＋Note QR

この構成なら、イラストは飾りではなく**読者の状況理解と感情移入**を担当し、公式画像は**事実の証拠**を担当する。全スライドをAIイラストにすると製品の実在感と検証性が下がるため避ける。

### 生成・版管理ルール

- 最初に人物ごとの正面・側面・背面、服装、持ち物、配色を1枚のキャラクターシートとして承認する（参考記事のキャラクターシート制作工程がそのまま前例）
- 1カルーセル内ではそのシート、画風、時間帯、光源、色調を固定し、場面だけを変える
- 生成画像にはロゴ、UI、コード、数値、吹き出し、QR、出典を書かせない
- 同一場面は最低2案を生成し、表情、手指、衣服、持ち物、背景の破綻が少ない版を選ぶ
- 画像の修正は元画像を上書きせず、`ai_initial` → `v002` → `v003` のように派生版として保存する
- 最終合成後に、スマホ縮小可読性、文字切れ、人物の同一性、事実と演出の混同をvision reviewする
- AI生成イラストを使用したことが読者の判断に関係する場合は、投稿文または制作クレジットで明示する

### 編集イラストの事実境界（最重要ルール）

イラストは**一次情報が述べていることだけの世界を描く**。絵が一次証跡のように見えることを防ぐため、場面設定は必ずEdition JSONのフィールドに紐づける。

- Relore版の例：before場面の「探し直す」は `source_fact` の「1つの実行でissueからPRまでを一気通貫で進める基盤として設計」の否定形として描く（＝従来は実行ごとに文脈が途切れる、という `selection_reason` / `aoi_note` の記述範囲内）
- after場面は「記憶を引き継いで次の実行へ」まで。実測値・対応範囲・精度は絵で示さない（`caveat` が「対応範囲や安定性はRepository状態に依存」を明記しているため、絵がそれを拡張して見える演出は却下）
- 各イラストスライドのフッターに `illustration: AI生成 / 解釈は5枚目のAOIの見方に対応` のようなラベルをsatoriで置き、絵が「公式の図」に見えないようにする
- 一次情報に存在しない比較（機能同等性、性能差）を絵の対比で暗示しない。対比が主張レベルにとどまることは現行4枚目のフッター文言（「機能同等性は未検証」）で担保済み

### 次の実証プロトタイプ

現行Relore版の全面置換はせず、**静的モックとして4枚目だけを比較対象にする**（ジェネレーターは変更しない）。

- A案：現行の2列テキスト比較（既存スライドをそのまま使用）
- B案：同じ開発者を左右に置いた「実行のたびに文脈を探し直す／過去の理由を引き継ぐ」の2場面イラスト。対比の根拠は `selection_reason` の「issueからPRまでの文脈が失われる現在のagent運用」と `source_fact` の一気通貫設計記述に限定する
- 共通：見出し・ラベル・説明・出典はsatoriで同じ文字列を後置き
- 判定：3秒理解、空疎感、事実誤認（絵が未検証の性能差を主張して見せないか）、人物一貫性、スマホ可読性

B案がA案を上回り、かつ事実境界チェックを全て通した場合のみ、表紙と5枚目へ同じキャラクターを展開する。

## SNSネイティブ高密度ポスター方向（2026-09-29 参考画像受理）

shugoさんからAIモデル比較のSNSインフォグラフィック（1枚完結型）を参考受理。評価ポイントは以下を Adopt / Adapt / Reject に分類して適用する。

### Adopt（採用）
- **フック語彙の番号付きセクション**:「1 最高性能ランキング」「2 価格の落とし穴」「今回いちばん異常なこと」— 好奇心を喚起する見出しを節単位で持つ構造は、現行8枚構成の各スライド見出しへ移植する。
- **結論バナー**: 最重要結論は色付きバナー+大サイズで1行。読みが流しでも落ちる。
- **ランキング/表の可視化**: スコア比較は卡片だけでなく順位・メダル・数値を直接図示する（一次データの可視化であり、解釈の断定ではない）。
- ** persona の声**: 「〜ですね」「PS:」などの語り手気配は人間味として有効。AOIFUTURE版は**事実の断定ではなく編集部の注目点の語り口**として取り込む（例:「編集部が今回いちばん面白いと思うのは…」）。

### Adapt（方針に合わせて変換）
- **1枚完結高密度 → 保存用サムネ+カルーセル**: 参考画像の密度は1枚完結型。AOIFUTUREは8枚カルーセルを維持しつつ、**表紙1枚に当該密度の要約版（POC: poster variant）**を持たせ、feed内stop-scroll力を上げる案を次回エディションでA/Bする。
- **emoji/落書き風アイコン**: 使用可。ただし性能・出来事の**断定を補強する用途**（✅実装済み系バッジ等）には使わない。感情・注目度の演出に限定。
- **敬遠されがちな比較軸（Intelligence×Cost×Speed…）**: 現行テンプレSlide 4「共通軸比較」の軸扩充として組み込む。各軸に一次情報の確認日を併記。

### Reject（採用しない）
- **数値の無出典掲載**: 参考画像のスコアはArtificial Analysis ベースと注記される风格。AOIFUTUREでは数値をchartの一次URL+確認日なしでは掲載しない。
- **未検証の性能序列断定**: 「〜が一歩抜けました」型の断定は edition JSON のsource_fact が支持する場合のみ。「編集部まとめ」 Frasings は interpretation 枠に分離。
- **emoji前提の事実表現**（😂😭で事実の深刻さを伝える等）: ファクトには使わない。

### 実装上の次スライス
1. `generate-news-carousel.mjs` に `--style poster` を追加し、高密度1枚 variant を生成（既存 edition JSON から複製、新規数据采集なし）。
2. 同一 edition で calm 8枚版と poster variant を生成し、第三者 reader評価でstop-scroll/保存/共有を比較。
3. 勝者方向をテンプレ正本へ反映。公開は既存ゲート通過後。

## 品質ゲート

1. 一枚一メッセージか
2. 390〜430pt相当の縮小表示でピンチなしに読めるか
3. 各スライドの主張がEditionの一次情報で裏づけられるか
4. 事実、AOIの解釈、未確認事項が混ざっていないか
5. 生グラフの簡略化で結論が変わっていないか
6. 右端・フッター・長文に切れや重なりがないか
7. 1〜7枚目の視覚的ブリッジが連続し、8枚目で閉じているか
